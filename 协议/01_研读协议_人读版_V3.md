# 书籍研读协议｜人读版 V3

作者：HeyDachui。适用：用户上传的一本书。方法依据：研读协议 V3。

## 1. 开始前先确认能不能执行

本包入口是 [SKILL.md](../SKILL.md)。用户先上传技能包，再上传书籍（PDF 或包含书籍的压缩包），然后发送「开始研读」。技能包和书籍分别上传即可，无须另写任务书。

只有书籍已上传、且用户已明确发送「开始研读」时，才获得本次执行授权。仅收到技能包时先等待，不研读示例、不生成结果，也不要求用户复述长口令。所需条件、缺书或多书时的处理见入口文件。

将此次口令如实记录为 `task_execution_status=AUTHORIZED_FOR_EXECUTION`、`dispatch_authorized=true`，`authorization_source` 写「用户在当前对话发送开始研读」。未获授权时不得开始，不能把协议已加载当成研读已获授权。

冲突优先级为：用户当前对话中的明确要求 → 本包入口 → 本协议 → AI技术字段 → 反例库。若冲突会改变范围、完成状态或交付结构，指出具体冲突，只暂停受影响动作。

一本书使用一个独立对话，不自行合并多本书。默认范围是整本实际上传的书；用户明确指定范围时如实记录。任何未读、不可读、缺失或未判断的承重对象都必须可见。

## 2. 我们要什么

真正研读材料，把值得保留的事实、观察、概念、思想、审美观点、解释、原则、方法、案例、反例、关系或有依据的假设，形成来源清楚、意思完整、以后能够被发现、读取和判断的候选知识。

每个候选同时起草两个独立对象：

- **完整知识卡**：保存完整知识本体、成立条件、类型结构、作者与来源分层、连续证据、边界、冲突和未知；不设统一字数上限。
- **知识短卡**：只负责发现和调用，保存短标题、精炼知识、触发情境、适用范围和完整卡读取指针；不得补证、改义或独立激活。

当前生产版本是一张完整卡对应一张短卡。完整卡未经用户审阅确认前，短卡必须`active=false`。一章可以0张或多张卡，不预设卡数。

## 3. 怎么读

先核对实际文件、书名、作者、文件版本标记、出版版次、印次和日期；这些身份分别保存，不把文件名中的`v1/v2`当成版权页版次。

先诊断文字层、页面、图表、目录／书签、标题层级、缺页、乱码、OCR、旋转和版式，再恢复阅读分母：

- 父级单元用于章节和范围导航；
- 叶级语义单元承载一个完整意思；
- 每个叶级语义单元恰好一个去向；父级单元不能用多个路由替代叶级拆分。

默认以有独立标题且承载完整意思的正文小节为叶级单元。无标题但承担独立论证、同章内证据状态不同或结论不同的连续范围可拆为子单元。案例通常并入所属小节；只有案例本身形成完整经验且证据独立时单列。图表只在承载正文未重复的新信息时单列。偏离默认粒度时说明原因。

扫描／图像材料使用双通道：

- 视觉读取负责页面完整性、图表、版式、方向、缺页和最终证据；
- OCR只辅助搜索和定位，承重摘录必须回到原始页面核对。

每个受影响单元分别记录：页面是否查看、主要承重内容是否读到、微文案是否已读／确认不承重新信息／可能承重新信息但不可读。装饰、重复或确认不承重新信息的微文案不单独强制不完整；可能带来新事实、步骤、条件、限制或案例判断而不可可靠读取时，必须写`INCOMPLETE_WITH_VISIBLE_GAP`。

局部缺页、乱码、OCR或版式问题记录范围后继续不受影响部分。身份严重冲突、系统性乱码、材料通道无法承重或其他足以使整体结果失真的重大问题，停止受影响材料并回报。停止也是真实结果，不强行产卡。

## 4. 来源与AI必须分开

尊重作者。作者观点按作者、版本和语境忠实保存；事实、因果和效果按相应证据处理。需要核验、补充、比较或反驳时可以联网，但指定材料、外部来源和AI派生分别保存，不能用外部材料反写作者原意。

每个承重事实、观点、步骤、条件、因果、范围、限制和效果，都必须有连续证据或明确AI身份。`claim_support`必须写到实际字段或数组项，不能用一句引文或一个宽泛的`type_specific_content`映射替整卡背书。

来源只承载观点或原则时，AI为可调用性补出的必要输入、步骤、筛选、重判条件、失败模式、产物或效果必须标为`ai_derived`，并进入具名AI提示；不能因为它受来源启发，就写成作者明确表达。

单个案例不能自动升级为通用方法；来源无法闭合技巧卡的目标、输入、步骤、分支和产物时，重分类为观点、观察、案例或证据不足。

## 5. 完成状态

`READING_COMPLETE`只在指定范围内实际存在的正文、承载信息的图像／表格、注释、附录及必要知识判断全部闭合时使用。

只要仍有未读、不可读、缺失、处理失败或尚未完成知识判断的承重对象，只能写`INCOMPLETE_WITH_VISIBLE_GAP`。登记缺口不要求强行读出，也不要求把全部潜在知识制卡。

文件生成、页数到达、OCR完成、卡数、路由数或自检通过都不能单独证明研读完成。

## 6. 怎么交付

标准结果ZIP根目录只含：

1. `研读成果_人读版.md`
2. `研读成果_AI版.json`

只有用户在当前对话明确要求额外建议、反馈或说明时，才把它作为ZIP外独立附件返回；额外附件不能改变标准ZIP结构。

以下任一情况都不是成功交付：

- 缺少或无法解析`研读成果_AI版.json`；
- 用协议、模板或任务书复制内容冒充结果；
- 人读版声称有卡或完成，但AI版相应数组为空或不一致；
- 机械自检为`PARTIAL/FAIL`却声称完成；
- 完整卡与短卡不一一绑定；
- 阅读叶单元没有唯一去向；
- 来源／AI边界混写或草稿状态自动升格。

0张卡可以是合格结果，但必须有真实阅读分母、叶级路由、证据／不制卡理由和可解析AI版。

所有结果只是待用户审阅的候选知识草稿，不代表已经确认、写入正式知识库、正式采用或效果得到验证。完整卡和短卡不得自行转为正式状态。
