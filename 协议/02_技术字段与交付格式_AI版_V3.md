# 书籍研读协议｜技术字段与交付格式 AI版 V3

作者：HeyDachui。适用：用户上传的一本书。
协议版本：`PORTABLE_CHATGPT_READING_V3_SOURCE_AI_LEAF_ROUTE`。

## 0. 输入、授权与优先级

完整读取本包 [入口](../SKILL.md)、[人读协议](01_研读协议_人读版_V3.md)、本文件和 [反例库](03_研读反例库_V3.md)，再处理用户另行上传的书籍。技能包只提供规则，书籍无需与规则装在同一包里，不要求用户另写任务书。

用户已上传书籍且发送「开始研读」时，获得本次执行授权，在结果中记录 `task_execution_status=AUTHORIZED_FOR_EXECUTION`、`dispatch_authorized=true` 和实际授权来源。只有协议或只有书籍时等待；缺少可访问的书籍或执行能力时报告真实缺口，不虚构访问和结果。

优先级：用户当前对话明确要求 → 本包入口 → 人读协议 → 本文件 → 反例库。一个对话只研读一本书，不跨书合并。

不要求手算文件与摘录哈希；对应值可以为 `null`，后续可对未改写对象补齐。不能虚构哈希。

## 1. 返回包与硬门

标准ZIP根目录恰好两个文件：

1. `研读成果_人读版.md`
2. `研读成果_AI版.json`

额外建议只在用户明确要求时放ZIP外。JSON必须是UTF-8、可独立解析的单个对象。缺少JSON、JSON为空、把合同复制成结果、人读／AI结果矛盾或自检`PARTIAL/FAIL`，都只能报告失败，不能写成功交付。

## 2. 人读版固定结构

```markdown
# 研读成果｜书名

## 一、材料身份与实际访问
## 二、材料质量、结构诊断与拆分结果
## 三、实际阅读范围与完成状态
## 四、知识短卡
## 五、外部研究、分歧与AI派生
## 六、未成卡叶级语义单元及唯一去向
## 七、未读、不可读、证据不足、停止事项与建议
```

人读版普通人可直接读懂；状态、数量、卡ID、路由与异常必须和AI版一致。


## 4. `task`

```json
{
  "assigned_scope": "整本实际上传的书；任何未读、不可读、缺失或未判断对象都必须可见",
  "special_objective": "按研读协议V3研读书籍",
  "producer": "当前实际执行的AI助手",
  "task_execution_status": "AUTHORIZED_FOR_EXECUTION",
  "dispatch_authorized": true,
  "authorization_source": "用户在当前对话发送开始研读",
  "instruction_precedence": [
    "用户当前对话明确要求",
    "SKILL.md",
    "协议/01_研读协议_人读版_V3.md",
    "协议/02_技术字段与交付格式_AI版_V3.md",
    "协议/03_研读反例库_V3.md"
  ],
  "additional_deliverables": [],
  "started_at": "",
  "completed_at": ""
}
```

以上路径以技能包顶层目录为基准。`assigned_scope`、`special_objective`、`producer`和时间按本次实际情况填写，不能照抄示例冒充已执行。

`task_execution_status`只能取`AUTHORIZED_FOR_EXECUTION`或`NOT_AUTHORIZED`。额外交付项结构为`name`与`placement=outside_required_zip`。未要求额外交付时数组为空。

## 6. `material_diagnostics`

```json
{
  "access_channel": "mixed",
  "native_text_status": "absent",
  "visual_content_status": "read",
  "structure_status": "recoverable",
  "observed_quality_issues": [
    {
      "scope": "整个PDF",
      "issue_type": "native_text_absent",
      "severity": "local",
      "fact": "无原生文字层",
      "impact": "OCR只能辅助定位",
      "action": "continued_unaffected_scope"
    }
  ],
  "split_method": "目录、标题层级、页码与连续语义",
  "split_summary": "",
  "major_stop_triggered": false
}
```

访问字段只能使用本文列出的实际值：

- `native_text_status`：`usable`、`partial`、`absent`、`garbled`、`unknown`；
- `visual_content_status`：`read`、`partly_read`、`not_present`、`not_accessible`、`unknown`；
- `structure_status`：`clear`、`recoverable`、`fragmented`、`conflicting`、`unknown`；
- `severity`：`local`、`major`；
- `action`：`continued_unaffected_scope`、`stopped_and_reported`。

## 7. `reading_denominator`：父级与叶级分开

`reading_denominator[]`同时登记父级导航单元和叶级语义单元：

```json
{
  "unit_id": "U010A",
  "parent_unit_id": "U010",
  "unit_role": "leaf",
  "unit_type": "section",
  "title_or_description": "",
  "declared_locator": "",
  "observed_locator": "",
  "boundary_basis": "正文小节标题与连续论证",
  "access_status": "readable",
  "reading_status": "read",
  "knowledge_judgment_status": "completed",
  "page_review_status": "reviewed",
  "primary_carrier_status": "read",
  "microtext_status": "not_load_bearing",
  "child_unit_ids": [],
  "route_ids": ["R010A"],
  "gap_or_note": ""
}
```

规则：

- `unit_role`只能取`parent`或`leaf`；
- 父级单元使用`child_unit_ids`，`route_ids`为空；
- 每个叶级单元恰好一个`route_id`；全部路由引用的叶单元不得重复或遗漏；
- `access_status`：`readable`、`partly_readable`、`unreadable`、`missing`、`not_provided`；
- `reading_status`：`read`、`partly_read`、`not_read`；
- `knowledge_judgment_status`：`completed`、`incomplete`、`not_possible`；
- `page_review_status`：`reviewed`、`partly_reviewed`、`not_reviewed`；
- `primary_carrier_status`：`read`、`partly_read`、`unreadable`、`none`；
- `microtext_status`：`read`、`not_load_bearing`、`potentially_load_bearing_unreadable`、`none`。

`potentially_load_bearing_unreadable`、缺页、不可读或判断未完成都强制整份结果为`INCOMPLETE_WITH_VISIBLE_GAP`。

## 8. 来源与外部研究

指定材料必须登记为`SRC-001`：

```json
{
  "source_id": "SRC-001",
  "source_type": "assigned_material",
  "title": "",
  "author_or_org": [],
  "version_or_date": "",
  "file_name_or_url": "",
  "accessed_at": "",
  "actual_read_scope": "",
  "role": "assigned_material",
  "reliability_basis": "",
  "limitations": []
}
```

外部来源逐项新增source；`external_research_records[]`保存问题、来源、实际发现、与指定材料的关系、影响卡ID和限制。只留URL不算证据。

## 9. `semantic_routes`

每个叶级语义单元恰好一个路由：

```json
{
  "route_id": "R010A",
  "unit_ids": ["U010A"],
  "semantic_unit_summary": "",
  "route": "candidate_knowledge",
  "target_card_ids": ["KC001"],
  "related_route_or_card_ids": [],
  "basis": "",
  "user_review_required": true
}
```

`route`只能取：`candidate_knowledge`、`merge`、`duplicate`、`case_project_material_only`、`insufficient_source`、`no_independent_knowledge_value`。AI只提候选建议；是否接受、采用或写入正式知识库，由用户审阅决定，不因生成结果而自动确认。


`kind`只能取：`事实`、`观察`、`概念定义`、`思想观点`、`解释模型`、`原则判断准则`、`技巧经验`、`案例经验`、`失败经验反例`、`决策规则`、`关系比较冲突`、`假设`。

类型专属字段如下：

- `事实`：`subject`、`statement`、`time_version_scope`；
- `观察`：`observed_object`、`observation`、`context`；
- `概念定义`：`concept`、`definition`、`distinctions`；
- `思想观点`：`proposition`、`reasoning`、`context`；
- `解释模型`：`explained_object`、`source_observations`、`explanatory_relation_or_mechanism`、`scope`；
- `原则判断准则`：`object`、`principle_or_criteria`、`how_to_apply`、`rejudge_when`；
- `技巧经验`：`goal`、`necessary_inputs`、`steps`、`branches_or_judgment_conditions`、`output`；
- `案例经验`：`context`、`actors_or_objects`、`actual_actions_or_events`、`observed_result`、`relevance_without_overgeneralization`；
- `失败经验反例`：`context`、`actual_failure_or_counterexample`、`evidence_pattern`、`confirmed_cause_or_unknown`、`source_carried_correction`、`non_transfer_boundary`；
- `决策规则`：`conditions`、`branches_and_actions`、`expected_outputs`、`reversal_conditions`；
- `关系比较冲突`：`objects`、`relationship_or_differences`、`basis`、`scope`；
- `假设`：`hypothesis`、`basis`、`testable_or_unverified_parts`、`scope`。

来源不能闭合类型字段时重分类；不能用模板补齐后仍标成作者明确表达。

## 11. `claim_support`：必须逐字段映射

```json
{
  "claim_path": "type_specific_content.steps[0]",
  "support_mode": "ai_derived",
  "evidence_ids": ["E001"],
  "note": "该步骤是生产者为调用而作的操作化，不归属于作者明确表达。"
}
```

`support_mode`只能取`assigned_material_explicit`、`external_supported`、`multi_source_synthesis`、`ai_derived`、`unknown`。

要求：

- 映射到真实字段或数组项；不得只写宽泛`type_specific_content`替多项主张背书；
- 一段证据可支持相邻主张，但必须逐项说明；
- AI补出的输入、步骤、筛选、重判、失败模式、产物或效果标`ai_derived`，`source_voice`加入`ai_derived_hypothesis`，并在`ai_derived_advisory`说明；
- 来源证据可作为AI操作化的启发依据，但不把AI字段升级为作者原意。

## 13. `evidence_records[]`

```json
{
  "evidence_id": "E001",
  "knowledge_card_id": "KC001",
  "source_ref": "SRC-001",
  "locator": "PDF第52页／印刷页33",
  "locator_basis": "电子页与印刷页并列核对",
  "excerpt": "未改写的连续原文",
  "excerpt_sha256": null,
  "extraction_method": "manual_transcription",
  "evidence_role": "支持具体主张",
  "quality_note": "OCR只辅助定位，摘录回到原始页核对"
}
```

`extraction_method`只能取`native_text`、`visual_read`、`ocr_locator_only`、`ocr_assisted_manual_verification`、`manual_transcription`、`web_page`、`other`。locator只是地址，不是证据。版式、图片或表格承重时写清实际视觉读取；没看见就登记缺口。

## 14. 自检与异常

`producer_self_review.batch_checks`至少包括：材料身份、父叶分母、每叶一路由、人读／AI一致、卡短卡一一绑定、引用存在、逐字段证据／AI身份、短卡不增义、标准ZIP两文件、额外附件在ZIP外。

逐卡检查：类型完整、正文独立、字段级`claim_support`闭合、来源／外部／AI／未知分开、唯一去向明确、短卡语义一致。

`unresolved_and_failures[]`字段：`failure_id`、`scope`、`failure_type`、`severity`、`fact`、`impact`、`action`、`still_unknown`、`suggested_follow_up`。

## 15. 交付前机械门

- ZIP恰好两个规定结果文件，JSON可解析且顶层字段匹配；
- 人读版和AI版身份、范围、状态、数量、卡ID、路由和异常一致；
- 父级单元不冒充叶级语义单元；每个叶级单元恰好一个路由；
- 全部ID唯一、引用存在、卡短卡一一绑定、版本与状态一致；
- 每个承重字段有连续证据或明确`ai_derived/unknown`；
- 扫描页面、主要承重内容和微文案状态真实；
- 缺页或潜在承重微文案不可读时，状态为`INCOMPLETE_WITH_VISIBLE_GAP`；
- 0张卡时仍有完整阅读分母、叶级路由和不制卡判断；
- 未把草稿写成用户已确认、正式知识库已写入、正式采用或有效；
- 自检必须`PASS`。失败或`PARTIAL`只报告真实失败，不包装成完成。
